For the developer

What changed in the knowledge bases on 15 Aug

  • Removed three test lines from the general KB — carpets, skateboards, and loud hours : 3am to 3pm (which read as permission to be loud at 3am).
  • Removed 45 stale room labels from the Hotel Molo Residence KB — channel-manager strings like 34 Boho (1). These were harmless: guest matching uses a different table (property_rooms), which was always correct. Nobody would say those out loud, so they were never reached. Tidy-up, not a bug fix.
  • Fixed the real bug: the general KB was being discarded once a guest was identified.
  • Backup of everything before the change: backend/supabase/kb-backup-2026-08-15.json

One room can't be in two knowledge bases — confirmed

There's a unique index on (property_id, room_number). Verified by trying an actual duplicate insert, which was rejected. Different properties can each have their own room 4 — that's allowed and correct.

The one gap, and how to close it

That protection only works when property_id is filled in. The column allows NULL, and Postgres treats NULLs as all-different in a unique index — so two rows with no property could hold the same room number. The dashboard always sends a property, so this can't happen from the UI, and there are zero such rows today. To close it permanently:

-- 1. confirm nothing would break (expect 0)
select count(*) from knowledge_base_rooms where property_id is null;

-- 2. require a property from now on
alter table knowledge_base_rooms
  alter column property_id set not null;

After that, the old API shape that omitted a property will fail loudly instead of quietly creating a duplicate. Worth also deleting that legacy roomNumbers branch in backend/supabase/functions/api/routes/knowledge-bases.ts.

Deploying

Agent ships from your local folder — git isn't involved. Root Dockerfile and livekit.toml are stale, so swap the pipeline versions in first:

cd backend/agent
cp pipeline/Dockerfile Dockerfile
cp pipeline/livekit.toml livekit.toml
lk agent deploy --project molo-residence
git checkout Dockerfile livekit.toml

Dashboard builds from GitHub main via Render — it must be committed and pushed. Root directory is frontend.

Still to deploy: the delete transcript button is built and pushed, but the API route behind it isn't live yet. Run supabase functions deploy api from backend/supabase/, or the button will error.

Things to know

  • Never edit agent.py — it's imported and treated as read-only. Everything lives in agent_pipeline.py; the prompt is in pipeline_prompt.py.
  • A bad voice ID fails silently at first speech, not at startup — the caller hears nothing for the whole call. This took the line down twice. There's now a fallback voice.
  • LiveKit only serves each provider's default voices — a voice picked from ElevenLabs' community library will not work.
  • "SMS sent" means queued, not delivered. There's no delivery confirmation.
  • Editing a KB in the dashboard takes effect on the next call. No deploy needed.
  • Tests — agent: uv sync --python 3.12 && uv run pytest (87 passing). Frontend: NODE_OPTIONS="--no-experimental-webstorage" npm test (34 passing).
